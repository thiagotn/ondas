# Handoff: Ondas — terminal-style music player (mobile-first, responsive)

## Overview
Ondas is an online music-streaming app with a look inspired by terminal emulators (Ghostty). It streams tracks using **live metadata**. It also has a **local buffer/cache** so tracks can play offline. Two access modes:
- **Guest:** listens only to free tracks. Can't download or play `[pro]` tracks.
- **Logged in:** full catalog plus offline downloads.

The user can switch between **9 terminal-style color schemes** (Catppuccin Mocha, TokyoNight, Dracula, Gruvbox, Nord, Rosé Pine, Solarized Dark, GitHub Light, Nocturne). The choice persists.

## About the design files
The files in this bundle are **design references built in HTML**: interactive prototypes that show the intended look and behavior. They are **not production code**. The task is to **recreate this design in the target codebase's environment** (e.g. React Native/Expo, Flutter, SwiftUI/Kotlin, or a React PWA) using its established patterns and libraries. **Decided stack for v1: PWA with React + TypeScript + Vite** (see "Target stack" below). Native apps will come later, so structure the code to make that easy.

`Ondas Terminal.dc.html` is a single self-contained component: template + a logic class (`class Component`, React-style with `state`/`setState`). The logic (fetching, playback, cache, keyboard shortcuts, themes) is a good reference for the business rules.

## Target stack (v1 — PWA)
- **React 18 + TypeScript + Vite.** Chosen over Svelte so the domain logic and hooks can be reused later in React Native/Expo.
- **PWA:** `vite-plugin-pwa` (Workbox). Precache the app shell. Use `injectManifest` for a custom Service Worker.
- **Offline audio:** Cache API (`ondas-offline`) for downloaded tracks, written from the main thread (as in the prototype) or from the SW. Call `navigator.storage.persist()` on the first download and show usage with `navigator.storage.estimate()`.
- **Metadata/state:** TanStack Query (with `persistQueryClient` to IndexedDB) for the catalog; Zustand for player/session/theme; `idb-keyval` for likes, the downloaded-tracks index and the session.
- **Audio:** a single `HTMLAudioElement` in a `PlayerEngine` module (no React inside), plus the **Media Session API** (title, artist, artwork, play/pause/next/prev/seek actions) for lock-screen and headset controls.
- **Styling:** CSS variables generated by `applyTheme()` (same formulas as the token section) + CSS Modules or vanilla-extract. Font `@fontsource/jetbrains-mono` (self-hosted, so it works offline).
- **Icons:** `@phosphor-icons/react`.
- **Routing:** React Router: `/login`, `/` (em-alta), `/buscar`, `/biblioteca`, plus a `?player=1` overlay so the back button closes it.
- **Manifest:** `display: standalone`, `theme_color`/`background_color` = current theme bg (update `<meta name="theme-color">` when the theme changes), maskable icons.
- **Network:** `navigator.onLine` + `online`/`offline` events. Keep the manual toggle only in a dev build.

### Known iOS/Safari limits (accepted for v1)
- Background audio works in an installed PWA, but iOS may suspend it. Smart-buffer downloads only run while the app is open.
- iOS can evict storage from PWAs that sit unused for a long time. Re-check `cached` against the Cache API on boot and drop entries that are missing.
- There's no Background Fetch. Downloads happen in the foreground with progress shown.

### Architecture ready for native (phase 2)
Monorepo (pnpm workspaces):
```
packages/
  core/        # pure TS, no DOM: types, access rules (premium/guest), queue/shuffle/repeat,
               # theme derivation (bg/fg/accent/ansi → tokens), API client + fallbacks, formatters
  web/         # Vite PWA: React UI, PlayerEngine (HTMLAudio), OfflineStore (Cache API)
apps/ (future)
  mobile/      # Expo: same core; PlayerEngine → react-native-track-player; OfflineStore → expo-file-system
```
Define **interfaces in `core`** and implement them per platform:
- `PlayerEngine { load(track, src), play(), pause(), seek(s), on(event) }` with events `time`, `buffer`, `ended`, `waiting`, `error`
- `OfflineStore { has(id), get(id) → playable src, put(id, stream, onProgress), remove(id), usage() }`
- `KeyValueStore { get, set }` (localStorage/idb on web → MMKV/AsyncStorage on native)
- `Connectivity { isOnline(), subscribe(cb) }`

UI components stay per platform. Tokens, rules and state (Zustand stores) live in `core` and are shared.

## Design tokens and theme system
Each theme defines only: `bg`, `fg`, `accent`, and 8 ANSI colors (`ansi-0..7`). **Everything else is derived** with `color-mix(in oklab, …)`:

```
--color-bg       = bg
--color-text     = fg
--color-surface  = mix(fg 6%, bg)
--color-accent   = accent
--color-neutral-N = mix(fg P%, bg)   N/P: 100/100 200/92 300/82 400/70 500/57 600/44 700/30 800/18 900/9
--color-accent-N:
   100 = mix(accent 25%, fg)   200 = 45% fg   300 = 65% fg   400 = 85% fg
   500 = accent
   600 = mix(accent 78%, bg)   700 = 55% bg   800 = 35% bg   900 = 18% bg
--ansi-0..7      = theme ANSI palette
--shadow-sm = 0 0 0 1px mix(fg 18%, bg)
--shadow-md = 0 0 0 1px mix(fg 30%, bg), 0 6px 18px rgba(0,0,0,.35)
--shadow-lg = 0 0 0 1px mix(fg 44%, bg), 0 16px 40px rgba(0,0,0,.45)
```
The vars are applied to `document.documentElement`. In native, use a theme provider that computes the same values (any OKLab color lib works).

### Semantic use of ANSI colors
- `ansi-1` red: offline status, "sair", like (filled heart), traffic light
- `ansi-2` green: `user@ondas` in the prompt, `[off]` tag, `[x]` checkbox, online status, login/password labels
- `ansi-3` yellow: `[pro]` tag, "aviso:", the gate border and title
- `ansi-4` blue: prompt `cwd`, library/full-player row labels
- `ansi-5` magenta: artist name
- `ansi-6` cyan: download progress `[ 42%]`
- genre `#tag` color = `ansi-(1 + hash(genre) % 6)`

### Spacing / radius
- radius-sm 4px (buttons, panels, rows); radius full on traffic lights
- Rows: min-height 50px, padding 4px 8px, margin 0 -8px (the hover bleeds out to the edges), gap 10px
- Minimum tap target 40–44px for all buttons

## Interactions and behavior

### Keyboard shortcuts (ignored while typing in an input, except Esc)
`espaço` play/pause · `n`/`p` next/previous · `←`/`→` ±10s · `/` opens search and focuses the input · `1` `2` `3` tabs · `l` like current · `d` download/remove current · `f` full player · `s` shuffle · `r` repeat-one · `o` toggle network (simulation) · `t` themes · `Esc` closes overlays. In the picker: `j/k/↑/↓`, `Enter`, `Esc`. In the gate: `Enter` → login. On mobile, every action also has a tap target.

### Access rules
- `premium(i) = i % N === N-1` (N = 3 in the prototype). **In production this comes from the API** (a field on the track).
- Guest + premium → opens the gate; nothing plays.
- Guest + download → gate (downloads require an account).
- Login: the prototype accepts any valid email + password ≥4. **Replace with real auth** (OAuth/JWT). The session persists.

### Playback
- First play with nothing loaded: plays the first unlocked track.
- `next/prev` skips locked tracks and, when offline, uncached ones. Shuffle picks at random. Repeat-one restarts the track.
- When a track ends: repeat, or next.
- Stream error: toast "stream indisponível — prévia simulada", then falls back to simulated playback (prototype only; in production, show an error and skip).

### Buffer / offline
- **Buffer level** = `audio.buffered.end(last) / duration`, shown in the waveform, the bar and `buf: +m:ss`.
- **Download**: `fetch(stream)` reads the body with a reader and progress (`content-length`), stores the Blob in the **Cache API** (`ondas-offline`, key `/offline/<id>`), and marks `cached[id]` plus its size in localStorage. Toast "salva no aparelho".
- **Smart buffer** (toggle, logged in only): when a track starts, silently downloads the **next unlocked track**. Toast "buffer: próxima faixa salva".
- **Playing cached tracks**: `URL.createObjectURL(blob)`; revoke the previous URL.
- **Offline mode**: only `[off]` tracks play. The rest drop to 0.4 opacity, and tapping one gives "sem rede — faixa não está no aparelho". Downloads are blocked ("conecte-se para baixar"). In production, use the real `navigator.onLine` / NetInfo instead of the manual toggle (keep the toggle as a dev/debug option, if useful).
- **Native implementation**: use the platform's equivalent (e.g. `expo-file-system` plus `react-native-track-player` with a cache, or ExoPlayer CacheDataSource / AVAssetDownloadTask). Add a Service Worker if it's a PWA.

### Metadata
- Prototype: **Audius public API**. `GET https://api.audius.co` → list of hosts (pick one at random) → `GET {host}/v1/tracks/trending?app_name=ONDAS_PROTO&limit=24`. Mapping: `id, title, user.name, genre (slugified, no accents), duration, artwork['480x480'|'150x150']`. Stream: `{host}/v1/tracks/{id}/stream?app_name=…`. 8s timeout.
- Fallback 1: metadata saved in localStorage (`meta`) → "metadados em cache local".
- Fallback 2: a demo catalog of 12 tracks with no audio → "catálogo demo — api inacessível".
- Replace this with your platform's backend; keep the same 3-level fallback chain.

### Waveform
The prototype generates the heights with a deterministic pseudo-random function seeded by `hash(id)` (`|sin(h·1e-4 + i·0.55)·0.6 + sin(i·0.17 + h%7)·0.4|` → 8 levels). In production, use real peaks (precomputed on the backend) and keep the character-based rendering.

### Loading / transitions
- Loading: `⠋ carregando metadados…` (neutral-500). Optional: animate the braille spinner.
- Buffering: `ph circle-notch` icon on play and `BUF` mode.
- No transition animations besides the cursor blink. Keep it snappy.
